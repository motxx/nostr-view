# ADR-0007: クラスタ同一性をメンバー重複で引き継ぎ、Auto選択にヒステリシスを設ける

- ステータス: 採用
- 日付: 2026-06-10

## コンテキスト

クラスタは10秒毎にライブデータから再計算される。位置依存ID（interaction-0等）とハッシュタグ由来のフィンガープリントはどちらもデータの蓄積で漂移し、実機検証で2つの問題を起こした: (1) LLM生成の見出しが再計算毎に揺れる（"Reserve Wars"→10秒後に別名）、(2) Autoモードで僅差のファセット同士（実測: interaction 0.585 vs engagement 0.582）が勝者交代を繰り返し、宇宙全体が再編成され続ける。見出しが「さっと頭に入る」体験には名前と区分の安定が必須である。

## 決定

1. **クラスタ同一性のメンバー重複照合**（`cluster-identity.ts`）: 再計算後、新クラスタを直前の同ファセットのクラスタとJaccard重複（≥0.3、貪欲1対1）で照合し、一致したら旧id・色・命名フィンガープリントを継承する。コミュニティの実体は「人の集合」であり、タグやサイズ順位ではない
2. **Auto選択のヒステリシス**: 現職ファセットは挑戦者がスコア差0.05超で上回らない限り維持する
3. 照合対象はファセット別に記憶し、Autoがファセットを往復しても各ファセット内の同一性は保たれる

## 結果

- 実機で2回以上の再計算をまたぎ見出し（雑談ラウンジ / Morning Dispatch / Stack Brigade等）が完全に安定することを確認
- LLM命名APIの呼び出しが「本当に新しいコミュニティ」だけに減り、コストが下がる
- 選択中クラスタのタイムラインが再計算で別コミュニティに差し替わる事故も同時に解消（idが実体に追従するため）
- トレードオフ: 継承の連鎖でフィンガープリントは「最初に観測された時点のキー」に固定される。コミュニティが徐々に完全入れ替わった場合も旧名が残り続けるが、Jaccard<0.3で連鎖は切れるため有界
