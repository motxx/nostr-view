# ADR-0002: コミュニティグラフをノート著者に限定し、フォローエッジを除外する

- ステータス: 採用
- 日付: 2026-06-10

## コンテキスト

インタラクショングラフを無制限に構築すると、kind-3フォローリストのpタグが「ウィンドウ内で一切発言していない」数万のpubkeyを流入させる。実測でモジュラリティは0.71から0.20に崩壊した。さらにフォローエッジ自体が問題を起こす: kind-3は数年分の累積フォローでありウィンドウ内の関与を反映せず、コミュニティ横断の密な網を張る。重みスイープではfollow=0.25ですら7コミュニティ（Q=0.78）が1つの157人塊（Q=0.17）に潰れた。

## 決定

1. **グラフのノードはアクティブユーザ（ウィンドウ内のノート著者）に限定する。** 可視化が描画するのもノート著者のみであり、クラスタ対象と表示対象を一致させる。SimClusters（KDD 2020）がproducerのみをクラスタするのと同じ原則
2. **フォローエッジは重み0で除外する**（`INTERACTION_WEIGHTS.follow = 0`）。コミュニティ検出はリプライ・リポスト・リアクション・zapの「ウィンドウ内の実関与」だけを使う

## 結果

- 実データ2セットでQ=0.675〜0.728、目視でも一貫したコミュニティ（cat/photography、日本語圏、bible、geopolitics等）を検出する
- カバレッジは21〜26%に留まる。これは6時間窓で大半の著者が他の可視著者と関与しないというデータの実態であり、アルゴリズムの欠陥ではない
- フォロー信号を将来活かす場合は、生エッジではなくSimClusters式のproducer-producer cosine類似度変換を実装する（docs/clustering.md「今後の拡張候補」）
