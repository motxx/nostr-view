# ADR-0005: クラスタリングと命名を一方向に分離する

- ステータス: 採用
- 日付: 2026-06-10

## コンテキスト

旧実装への不満は「AIが作成したタグを元にしたクラスタは仮説検証されていない」だった。LLM出力は非決定的であり、クラスタ構成に混ぜると再現性と予測可能性が失われる。一方でクラスタの「読みやすい名前」には言語モデルが有効である。

## 決定

処理を一方向パイプラインに固定する: **構造でクラスタ → c-TF-IDFで初期ラベル → LLMは表示専用の磨き**。

1. メンバー構成はグラフ構造と統計のみで確定する。LLMは関与しない
2. 初期ラベルはc-TF-IDF（Grootendorst 2022, BERTopic）で「そのクラスタに特徴的なタグ」上位3つ。全クラスタ共通タグ（#nostr等）を自動的に沈める
3. LLM命名は非同期で実行し、結果は`clusterLabelOverrides`にクラスタ本体と分離して保存、表示時にのみ上書きする。同定はフィンガープリント（上位5ハッシュタグの内容ベース）で行い、再計算でIDがずれても名前を引き継ぐ
4. ラベルが決定的な面（Language・Engagement）は`labelLocked: true`でLLM送信を省く

## 結果

- クラスタ構成は同一データで常に同一。LLM障害時もクラスタは正常表示される
- LLMコストはフィンガープリント単位のキャッシュで抑制される
- 当初の弱点（ハッシュタグの無いクラスタの位置依存フィンガープリントによる再命名・取り違え）は、メンバー重複によるクラスタ同一性の引き継ぎで解消した（[ADR-0007](0007-cluster-identity-reconciliation.md)）
