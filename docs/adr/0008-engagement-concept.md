# ADR-0008: エンゲージメント（受信ベース・相互性込み）を単一の中心性概念とする

- ステータス: 採用
- 日付: 2026-06-10

## コンテキスト

旧influenceスコアは `followers + reactions×0.5 + reposts×2 + notes×0.1` で、3つの欠陥があった: (1) `notes×0.1` により大量投稿だけでスコアが稼げる（スパム脆弱）、(2) zap・リプライ・引用を無視、(3) 3D配置に一切使われず、放送型インフルエンサーが外周を漂う（実測: 影響力2位・85.1点のユーザが会話グラフ次数1）。要件: スパムは低く、インフルエンサーは高く、相互に会話する人はそのクラスタ内で高く。構成は検証可能であること。

## 決定

1. **エンゲージメント = 他者から受信したインタラクションの意図重み付き和 + 相互性ボーナス**（`engagement.ts`）
   - `receivedScore = Σ weights[type] × received[type]`（重みはグラフと同じ表: zap 4 / reply 2 / repost・quote 1.5 / reaction・mention 1）
   - `score = receivedScore + 2.0 × 相互パートナー数`（双方向のやり取りがある相手の数）
   - 投稿数はスコアに入れない（受信ベース→スパムは構造的に0点。自己参照はエッジ抽出で除去済み）
   - 内訳（種別ごとの受信数・inbound/相互パートナー数）をすべて保持し、UI（NodeDetailCard）に表示。スコアは内訳から再計算可能
2. **クラスタ文脈のエンゲージメント** `calculateClusterEngagement`: 同一クラスタのメンバーから受けた分のみを集計
3. **求心配置** `forceClusterCore`: クラスタ内エンゲージメントのパーセンタイルに比例して自クラスタ重心へ引く力を追加。コミュニティ構造を保ったまま「中心=そのコミュニティで最も関与を集める人」を実現
4. 適用範囲: ノードサイズ/ティア/配置、Engagement面（RFMのE次元）

## 係数の検証（実データ2セット、合格基準到達につき調整終了）

| 基準 | データセットA | データセットB |
|---|---|---|
| スパム（投稿≥5・受信0）が全員0点 | PASS (12人全員0) | PASS (2人全員0) |
| 重み撹乱でのtop-10安定（≥7/10） | 9〜10/10 | 7〜10/10 |
| スコアと「受信相手の人数」の順位相関 > 0.7 | 0.953 | 0.898 |

トップは「29人から17 zap+19リアクション」のような広い注目の持ち主であり、単一ソースの汲み上げではないことを確認。
再現: `bun scripts/eval-clustering.ts run` の「Engagement coefficients」セクション。

## 結果

- スパム耐性・インフルエンサー中心配置・相互会話の評価が単一概念で整合
- 重み係数はアドホック初期値のまま受理（撹乱に頑健と実証されたため過学習調整はしない）
- followerCountは表示用に保持するがスコア外（kind 3は窓内の関与でないため。ADR-0002と整合）
